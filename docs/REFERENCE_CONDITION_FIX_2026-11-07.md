# 实际参考图传递修复

本次修复位于新版 photo-workflow 的 continuity 路径，而非旧 V2.5 V5 目录。

## 已发现的问题

`api/continuity-generation.mjs` 的 Seedream 适配器在上游验证了 identity/scene/style 三类图，但发送时仅筛选 identity/style，并在三图处截断。因此“参考完整”的元数据检查不能证明场景图片参与了生成。另外，指定 anchor 母图读取失败时仍会继续发出请求。

## 实现

- 发送所有已验证角色参考图，已接受母图存在时放在首位。
- 锁定母图不可读取时抛出 `GENERATION_ANCHOR_MISSING`（409），不请求上游，不降级。
- 保留单镜头生成、现有镜头合同与人工 QC，不宣称生成成功即审美通过。
- 新测试检查实际请求 body.image 包含母图加三类参考，以及母图失效时没有上游请求。

## 验收边界

本轮以 mock 验证传输及失败行为；未调用收费接口、未生成新图。之后的 Worker 部署已包含这项参考图传递修复，但该部署尚未通过真实 Seedream 请求验证图像质量，也未重启现有本机实例。不要把 mock 或 Worker 上传成功表述为实际生图验收通过。

后续真实验证须使用已配置且获准使用的服务及用户授权素材：先测试一镜头，保存实际发送参考角色与请求ID，检查输出脸、场景、服装、光向、镜头、参考风格；人工认可后才扩展组图。不可借此恢复旧SD1.5路线或自动切换收费模型。

本机8123的 serve-continuity 路由生成调用没有注入 env，其 providers 推荐也使用 configuredEnv={}；因此该本机工具的列表不能证明线上凭证未配置，也不能证明线上图像服务已接通。部署前应核对实际服务入口和安全凭证注入，禁止读取或输出密钥。
