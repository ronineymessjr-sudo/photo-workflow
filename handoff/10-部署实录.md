## 三个真 bug（都是在真环境跑才暴露的）

### 1. `Buffer is not defined` → 上传直接 500

`wrangler.toml` 的 `compatibility_date = "2024-01-01"`，在这个日期下 `nodejs_compat` **不注入全局 Buffer**。

修法：在 `api/continuity-assets.mjs`、`api/continuity-generation.mjs` 顶部显式 `import { Buffer } from 'node:buffer'`。

为什么不用改 compat 日期：那会全局改变 fetch/crypto 行为，牵一发动全身。显式导入只影响这两个文件。

顺带：`/api/continuity/*` 的 500 现在会带 `code: CONTINUITY_INTERNAL` + 真实 message。之前的"服务器暂时不可用"根本没法查——这个 bug 就是这么找到的。

### 2. Workers AI 从未被推荐 → `manualOnly` 一直是 true

`/api/continuity/providers` 只传了 `configuredEnv`，没传 `bindings`。推荐器看不到 `env.AI`，于是永远回落到手动通道——**哪怕这个部署明明有绑定**。

修法：`recommendProvider({ ..., bindings: { AI: env.AI } })`。

修完立刻变：

```
推荐: cloudflare-flux-klein
manualOnly: false
API 可用: cloudflare-flux-klein
```

### 3. 参考图跨请求丢失 → 生成报 `GENERATION_REFERENCE_MISSING`

没有任何存储绑定时，资产落进**每个 isolate 的内存**。上传成功了，下一个请求就找不到字节。

R2 需要先在 Dashboard 启用（要绑支付方式），所以这次先走 **KV**：

```
[[kv_namespaces]]
binding = "CONTINUITY_KV"
id = "0ad84e60521a4089825a0e81f19a2d50"
```

KV 免费额度 1GB / 每天 10 万次读，参考图单张 700KB 左右完全够。代码本来就有优先级 `R2 → KV → 内存`，以后启用 R2 只要加 `CONTINUITY_ASSETS` 绑定，**代码不用改**。

## 还缺什么（按重要性）

### 1. R2（可选，但建议）

KV 存参考图能用，但 KV 的设计是"读多写少"，而且**没有列目录能力**（`list` 要额外 API）。R2 更合适：

- 去 Cloudflare Dashboard → R2 → 启用（要绑卡，有免费额度 10GB）
- 然后 `wrangler r2 bucket create continuity-assets`
- 在 `wrangler.toml` 加：
  ```toml
  [[r2_buckets]]
  binding = "CONTINUITY_ASSETS"
  bucket_name = "continuity-assets"
  ```
- 重新 `wrangler deploy` 即可，代码自动优先用 R2

### 2. DeepSeek 密钥（质检要用）

生成完是 `qc: pending`，视觉初筛需要 `DEEPSEEK_API_KEY`：

```bash
wrangler secret put DEEPSEEK_API_KEY
```

不配也不影响出图，只是质检要人工勾。

### 3. Pages 的 Git 集成没连上我的分支

`photo-workflow` 项目是 Git 集成的，但它监听的不是我这条分支，所以这次是**手动 deploy** 上去的。下次 push 不会自动更新。

要么把生产分支指向 `fix/multi-pose-library-generation`（或合并到 main），要么继续手动部署。

### 4. 生产的允许来源（已含新域名）

`AI_STUDIO_ALLOWED_ORIGINS` 里有 `photo.ronineymessjrstudio.cn`，同域调用不触发跨域问题，这块不用动。
