## 二、还没配的三处（都不是代码问题，是凭据/资产）

| 缺口 | 证据 | 影响 |
|---|---|---|
| **本地 AI 密钥未配置** | `GET /api/ai/local-config` → `{"configured":false}`；`plan-lite` 返回 `modelCalls: 0, modelStatus: "not-configured"` | 检索只能靠关键词，语义理解、风格提取、视觉质检都没上 |

## 三、两条链还没接上（这是真正的缺口）

```
AI Studio:  输入 → 检索 PoseAtlas（295 条）→ 选参考 → 提案 → 确认 → 飞书
连续性组图:  建契约 → 三档参考 → 主图确认 → 逐镜请求/交接 → 质检
```

两边都在讲"参考图"，但用的不是同一套结构：

- AI Studio 的 `selectedTemplates` 是**图库条目**（`external_reference`，没有可下载的字节，`assetUrl: null`）；
- 连续性契约要的是 **identity / scene / style 三档、必须有本地资产**（`references[].path` 指向已入库的图片）。

所以现在点"确认提案"之后，参考图进不了组图契约——中间少一个转换层。

## 四、建议的下一步（按性价比）

1. **配本地 AI 密钥**（1 分钟）：把 DeepSeek key 存一次到本地加密库（或设环境变量），`plan-lite` 立刻从关键词升到语义理解，`modelCalls` 会从 0 变正数。
2. **接转换层**（半天）：新增 `/api/continuity/from-studio`，把 `selectedTemplates` 映射成三档参考：
   - `portrait / styling` → identity（或 style）
   - `costume` → style
   - `pose` → 对应镜头的构图约束
   由于图库条目没有字节，转换后仍标记 `pending`，提示用户补一张自己的授权图。
3. **接一个便宜画图 API**（10 分钟）：SiliconFlow FLUX Kontext，填两个 env，`manualOnly` 变 false。
4. FaceID 本地那套最后再说——先把"能用 API 跑通"的闭环打通。

## 五、一句话结论

**Codex 那边把"搜索 → 提案 → 飞书"这条链部署好了，本地服务是活的；但"参考图 → 生成 → 质检"这条还没通**，缺的是：AI 密钥、图像服务凭据、以及图库条目到组图契约的转换层。
