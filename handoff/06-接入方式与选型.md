# 接入方式与选型（脑子 / 画笔分离）

## 一、先把两件事分开

| 角色 | 谁来做 | 为什么 |
|---|---|---|
| **脑子**：理解需求、出分镜、审图 | **DeepSeek API**（固定一个，不用换） | 它本来就是干这个的；看图理解、输出结构化判断都是它的强项 |
| **画笔**：把字变成图 | 可插拔，你选 | 价格、参考图能力、画幅控制差异极大，绑死一家不划算 |

所以：**本地模型不是必须的**。我上一轮说"装本地 FaceID"，是因为要"同一张脸"这个硬指标；如果你能接受"像但不必同一人"，纯 API 就能跑。这个取舍由你定。

## 二、画笔注册表（`api/continuity-providers.mjs`）

按"便宜优先 + 是否能带参考图"排序，当前登记：

| ID | 价格档 | 参考图 | 上限 | 角标 | 适合 |
|---|---|---|---|---|---|
| `siliconflow-flux-kontext` | 便宜 | ✅ | 4 | 无 | **白底换脸、局部改图首选** |
| `zhipu-cogview` | 便宜 | ✅ | 3 | 有 | 批量试稿 |
| `manual-chatgpt-web` | 便宜（订阅制） | ✅ | 3 | 有 | 验证阶段、少量精修 |
| `volcengine-seedream` | 中等 | ✅ | 6 | 无 | 多参考合成 |
| `aliyun-wanx` | 中等 | ✅ | 3 | 有 | 人像风格化、电商图 |
| `gpt-image-2` | 偏贵 | ✅ | 16 | 无 | 质感要求最高的成片 |
| `minimax-image` | 中等 | ❌ | 0 | 无 | 只能概念稿，**不能用于连续组图** |

> 价格只给档位不给数字：图像 API 的单价按月变、按区域变，写死会过期。每条的 `console` 字段给的是控制台地址，自己核。

## 三、"找便宜的接" 已经写成函数

```js
recommendProvider({ needReferences: true, configuredEnv })
// 无凭据 → recommended: 'manual-chatgpt-web'，manualOnly: true
// 配了 SiliconFlow → recommended: 'siliconflow-flux-kontext'
```

接口：`GET /api/continuity/providers?needReferences=true&maxPriceTier=low`

返回里带 `recommended` / `configuredIds` / `apiReadyIds` / `manualOnly` / `blockedReason`，前端直接照着渲染，不用自己判断。

## 四、选好之后钉在契约上

`POST /api/continuity/provider { group, providerId }`

- 把 `imageProvider` 写进契约，后续生成默认用它；
- **切换画笔不会动锁定字段**（有测试守着）；
- 选了不支持参考图的服务（比如 `minimax-image`）会被直接拒绝——它锁不住人，不能进连续组图。

## 五、DeepSeek 视觉质检：现在怎么用

```bash
node tools/vision-check.mjs --image out.png \
  --size CU --camera "平视, 85mm" \
  --wardrobe "白色露肩上衣" --location "白底影棚" --weather "室内"
```

密钥两条来源，都不落明文：

1. 环境变量 `DEEPSEEK_API_KEY`；
2. Windows DPAPI 加密库（`%LOCALAPPDATA%\PhotoWorkflow\local-ai.json`），本地面板保存过一次就能复用。

当前本机是**未配置**状态，命令会明确报错并给出两种配置方式，不会假装通过。

判定规则是不对称的：**视觉只能把问题判成"不通过"，不能替你判"通过"**；身份、肢体、风格三项仍要人眼。

## 六、下一步只剩一个决定

- **要"同一张脸"** → 必须 FaceID（本地）或后处理换脸，参数已在 `comfy/fusion.config.json`；
- **接受"像"** → 现在就能接 `siliconflow-flux-kontext`（便宜 + 支持参考图），填两个 env 即可跑。

两条路都通了，缺的只是你选哪条。
