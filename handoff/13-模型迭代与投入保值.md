# 13 · 模型迭代了，这套东西还剩什么（2026-11-07）

回答一个问题：**模型一升级，我们做的这些是不是就白做了？**

## 先看事实

今天从 Cloudflare FLUX 换到火山 Seedream，改动了 29 个文件。

| 层 | 今天改了几次 | 举例 |
|---|---|---|
| `api/`（适配层） | 29 | 提示词组装、步数、翻译、景深转译、新 provider 适配器 |
| `tests/` | 15 | 断言跟着适配层变 |
| `tools/` | 9 | 出图脚本、干跑工具 |
| **`experiments/`（方案库）** | **0** | 28 个系列、259 个分镜，**一个字没改** |

`06-prompts-all.json` 最后一次改动是 2026-11-06，不是今天。

**这就是答案的形状：方案层没动，适配层全在重写。**

## 会贬值的（耗材）

这些是"为了迁就当前模型"而做的工作，模型一换代就要重调：

| 项 | 为什么贬值 |
|---|---|
| 提示词压到 512 token 以内 | 新模型上下文可能是 10000 token |
| 采样步数 4 → 24 | 新模型的最优步数完全不同 |
| 中文先翻译成英文 | Seedream 原生中文，这个步骤已经不需要了 |
| `f/8` 转译成 `Deep focus` | 纯适配某家文本编码器的理解能力 |
| 不能把黑白线稿和照片混着传 | 新模型可能天生支持混合语域 |
| 参考图上限 4 张 / 14 张 | 跟着模型走 |

**诚实说：这些占了我这两天工作量的一大半，而且确实会过期。**

## 不会贬值的（资产）

| 项 | 为什么保值 |
|---|---|
| **28 个拍摄方案 / 259 个分镜** | 这是摄影知识：什么题材配什么光、什么景别、什么构图。模型不知道"美术馆旋转楼梯该用 16mm 俯拍" |
| **验收标准**（QC 7 项 + 每镜 must_show / reject_if） | 这是审美判断。模型再强也要有人说"这个不合格" |
| **参考图角色划分**（脸/服装/场景/姿势各管一件事） | 这是工作流设计，模型只管吃图，不管该喂什么 |
| **锚点链式流程**（先定妆 → 后续编辑） | 这是拍摄流程，和用哪家模型无关 |
| **可追溯记录**（每张发了什么、用了谁、seed 多少） | 工程治理。出了事能定位是方案错还是模型没执行 |
| **失败案例库** | 哪些组合出不来——比成功案例更值钱，且模型换代后大部分仍然成立 |

## "最新模型随便碾压" 是个错觉

新模型确实能出更好看的**单张**。但它不解决这四件事：

1. **它不知道你要什么** —— 提示词还是人写。你今天看到我改了多少次提示词才把"不这么正"改对
2. **它不管九张一致** —— 这是行业级难题。Seedream 也只是"内容关联"，不是"同一个脸"
3. **它不替你验收** —— "这张能不能交付"是判断，不是生成
4. **它不知道客户改了需求怎么办**

模型的进步方向是"更听话"，但**"要什么"和"算不算过"永远要人说**。

## 模型越强，这套东西越值钱

因为瓶颈会移位：

| 阶段 | 瓶颈 | 谁赢 |
|---|---|---|
| 2023 | 能不能生成 | 有 API 的人 |
| 2024 | 像不像照片 | 会写提示词的人 |
| 2025 | 一不一致 | 有参考图管理的人 |
| 2026 | **拍什么、谁验收、怎么稳定交付** | **有方案库和验收标准的人** |

现在瓶颈已经在第三、四格。**模型越强，越不缺"能出图的人"，越缺"知道该出什么图、并能保证批次稳定的人"。**

## 怎么让投入保值（四条）

### 1. 领域层做厚，适配层做薄

现在的分层是对的，要继续守住：

```
方案库（JSON，模型无关）        ← 厚，越积越多
      ↓
契约层（locked / references / QC，模型无关）   ← 厚
      ↓
适配器（每家 200 行）           ← 薄，换模型只改这层
      ↓
模型
```

今天验证过了：换 Seedream 只新增一个适配器，方案库、契约、QC 一行没改。

### 2. 把方案库当"评测集"用

这是把"模型迭代"从威胁变成免费升级的方法：

> 新模型发布 → 用**同一组固定方案**（比如 6 个分镜）跑一遍 → 和当前基线对比一致性与质感 → 10 分钟知道该不该换。

有了固定评测集，**模型迭代不再是风险，是白捡的升级机会**。没有评测集，每次换模型都是赌博。

### 3. 沉淀失败案例库

比成功案例更值钱的东西：

- 哪些提示词写法会让模型崩（"人物最多占 40%"被理解成不画人）
- 哪些参考图组合会互相污染（白底影棚照 → 全片棚光）
- 哪些字段模型根本不认（`f/8 1/1000s`）

这些规律**跨模型成立**，因为新模型往往继承同类限制。

### 4. 记录每一次生成的完整上下文

已经做了（`sentPrompt` / `referencesSent` / `anchored` / `seed` / `provider`）。

这不是为了好看，是为了**换模型时能回答"到底是方案变差了还是模型变差了"**。没有这个，每次升级都是黑盒。

## 一句话总结

**模型是画笔，不是摄影师。**

客户买的不是"一张 AI 图"，是"一套能稳定出片的流程 + 可复现的交付"。画笔每半年换一支，摄影师的手艺、审美和流程不该跟着重学一遍。

我们这两天做砸的部分，恰恰都是"调画笔"（提示词压缩、步数、翻译）；做对的部分，都是"定流程"（角色分工、锚点、验收、可追溯）。

**后者才是你的核心。**
