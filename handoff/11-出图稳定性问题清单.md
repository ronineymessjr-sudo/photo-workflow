# 11 · 出图稳定性问题清单（2026-11-07）

给「那边」看的版本：每一条都带证据和修法，按影响排序。

## 结论先说

产出不稳定**不是提示词写得不够花**，是四个机制层面的问题：

1. 提示词**超出模型预算**（700 tokens vs 512 上限），关键约束全在尾巴上
2. 采样**步数用的是"构思档"**（4 步），不是成片档（约 25 步）
3. 参考图**视觉语域不一致**（两张写实照片 + 一张黑白人体线稿）
4. 参考图**内容与目标场景不匹配**（白底棚拍照 → 白底棚拍结果）

前两条已经改掉。后两条要换素材，需要你那边决定。

## 一、已修（本次改动）

### 1. 提示词超预算：700 → 408~504 tokens

**证据**：干跑 6 条实测

```
shot-01  1967 字符  ≈750 tok   ← 修前
shot-09  2025 字符  ≈797 tok
```

而 Black Forest Labs 对 FLUX.2 klein 的说明是：

> Prompt cap ~512 tokens — longer **degrades quality, doesn't truncate gracefully**.

我原来的结构把最关键的约束放在**最后**：

```
[主体+参考图角色] [shot direction] [must contain] [reject if]
[framing] [真实感块] [avoid 列表]
                          ↑ 超限时最先被牺牲
```

所以"必现""禁项""毛孔/光衰减"这些写了等于没写。

**修法**：

- 整体压到 400 出头
- 逐字段设上限（prompt 220 字、姿势 70 字、光线 80 字）
- 验收列表只留前 2 项，每项 ≤20 字
- 英文标签缩短（`The frame must contain:` → `Must contain:`）
- 翻译指令加"≤90 words，压重复不要扩写"

**结果**：408 / 417 / 418 / 433 / 440 / 504 tokens（按中文估算，翻译成英文后还会再降约 20–25%）。

### 2. 采样步数：4 → 24

**证据**：`compileCloudCandidateRequest` 里写死 `steps: 4`。而官方给的用法是

> Concepting: 4–8 steps（4B 变体，亚秒级预览）
> **Polish: ~25 steps on the 9B variant — texture, microdetail**

我们用的是 9B，却一直跑在"构思"档。这是"出图糊、皮肤假"的直接原因之一。

**修法**：`steps = 24`。代价是单张从 3–5 秒变成 15–25 秒左右。

### 3. 姿势参考图是黑白人体线稿（语域冲突）

**证据**：我下载了 `full_single_P017_front.jpg` 看——**是黑白人体结构线稿，而且是裸露的**。

官方明确写着：

> Multi-reference alignment: **mixing a watercolor + a photoreal + a 3D render in the same call confuses the editor.** Pick one consistent visual register across all refs.

我们当时是：白底写实人像 ×2 + 黑白裸露线稿 ×1 → 必然混乱，而且裸露人体图会污染身体和服装生成。

**修法**：姿势改成**文字**传递（方案里 `model_pose` 本来就写得很细），参考图只留 2 张写实照片。

```diff
- 参考图 3 张（脸 + 服装 + 线稿姿势）
+ 参考图 2 张（脸 + 服装），姿势走文字：Required pose: 后仰坐・单膝立起
```

### 4. 六个字段从没进过提示词

**证据**：逐字段比对（上一轮已修，这里并入清单）

| 字段 | 状态 |
|---|---|
| `lighting_setup` 光线 | 现在进 |
| `must_show` 必现 | 现在进 |
| `reject_if` 禁项 | 现在进 |
| `crop_boundary` 裁切 | 现在进（并入景别） |
| `shot_props` 道具 | 现在进（"无"也明说） |
| `aperture/shutter` | **转译成景深描述** |

最后一条特别说明：`16mm f/8 1/1000s` 对模型是**无意义字符**。现在转成

```
f/8  → Deep focus: the whole scene is sharp from foreground to background.
f/1.8 → Very shallow focus: only the face is sharp, background falls into soft blur.
```

## 二、要你那边决定的（我没法自己修）

### 5. 风格参考图决定服装 —— 现在是白底抹胸人像

**现象**：不管方案写什么衣服，出图永远是抹胸/背心。

**原因**：提示词里明确说 "Image 2 supplies the outfit exactly"，而 Image 2 是那张白底抹胸人像。模型照做了——它把参考图里的衣服**精确复制**过来了。

**这不是 bug，是设计生效了**，只是素材不对。

**要什么**：每个系列配一张**目标服装的实拍图**（正面、全身、无遮挡）。没有的话，服装只能靠模型发挥。

### 6. 人脸参考图是白底影棚照 → 白底光会污染结果

**现象**：明明要黄昏街头，出来还是柔和均匀的棚光。

**原因**：脸的参考图是白底、正面平光、无环境。模型同时学到"这个人的脸"和"这种布光"。

**要什么**：身份参考图最好是**目标场景下的照片**（同样的光、同样的环境），而不是证件照式白底。做不到的话，就得在提示词里用更强的光影描述去压它——但压不彻底。

### 7. seed 不保证系列一致

同一个 seed 只对**同一段提示词**有复现意义（其实还要同硬件）。换景别、换机位后，seed 相同也会是另一张图。

系列一致性真正靠的是：
- 同一组参考图（脸、服装）
- 同一套场景与光线描述
- 同一套调色指令

这三样我们现在都有，**唯一缺的是"同一个人的脸"** —— 那是模型能力问题（见下）。

## 三、模型能力边界（改不了，只能绕）

| 限制 | 数值 | 影响 |
|---|---|---|
| 提示词上限 | ~512 tokens | 超出即劣化，不是优雅截断 |
| 参考图张数 | 最多 4 张 | 超过会稀释引导，且必须语域一致 |
| 分辨率上限 | ~2K | 要更高得换 Seedream |
| 宽高比上限 | 16:9 | 极端竖幅会被裁 |
| 文字渲染 | 弱 | 图内不要指望有正确文字 |
| 4 步蒸馏 | 4/24 步差距巨大 | 必须用 20+ 步 |

**最关键的一条**：这个模型**没有 face embedding**。它把参考图当"风格提示"用，不当"身份约束"。所以：

> 单张质量可以做到能看，但**"一次拍摄、九张同一个脸"它做不到**。

要那个效果只有三条路：GPT Image 编辑模式（保人最好）/ 本地 IP-Adapter FaceID / 出图后统一换脸。

## 四、稳定性到底靠什么

四根柱子，缺一根就不稳：

1. **提示词在预算内**（≤450 tokens）且**重要约束前置** ← 已修
2. **步数够**（20–25）← 已修
3. **参考图语域一致 + 与目标场景匹配** ← 需要换素材
4. **出图后验收，只重做失败的那一镜** ← 机制已有（QC 7 项），但需要视觉模型密钥才能自动跑

第 3 条是现在最大的短板。
