# 09 · 为什么连不上（2026-11-07 实测诊断）

## 结论先说

不是网络问题，也不只是"被墙"这么笼统。**是 `*.workers.dev` 这个域名被定点封锁，而且是两层叠加**：

1. **DNS 投毒** —— 解析被改写成一堆无关公司的 IP
2. **SNI 阻断** —— 就算绕过 DNS 拿到真实 Cloudflare IP，TLS 握手照样被掐

同一个账号下的自定义域名 `photo.ronineymessjrstudio.cn` **完全正常**，所以底层网络是通的。

## 证据

### 一、DNS 被投毒（多个解析器返回不同假 IP）

| 解析途径 | 返回的 IP | 归属 |
|---|---|---|
| 本地 DNS（192.168.1.1） | `199.16.158.104` + `2a03:2880:...:face:b00c:...` | Twitter + 恶搞 IPv6 |
| 阿里 DoH（dns.alidns.com） | `31.13.82.33` | Facebook |
| 腾讯 DoH（doh.pub） | `157.240.0.35` | Facebook |
| 8.8.8.8 | `108.160.167.167` + `face:b00c` | Dropbox |

一个 Cloudflare Workers 域名，被四个解析器指到四家不同公司——**这不可能是上游配置问题**。

### 二、绕过 DNS 也连不上（SNI 层被阻断）

用 `--resolve` 强制指向 Cloudflare 真实边缘 IP：

```
--resolve photoatelier-api.photomagic.workers.dev:443:104.21.9.202    → 000，10s 超时
--resolve ...:172.67.189.143                                          → 000，10s 超时
--resolve ...:104.16.0.1                                              → 000，10s 超时
```

`104.21.9.202` 正是 `photo.ronineymessjrstudio.cn` 在用的 IP，那个域名 200 正常。**同一 IP、同一端口，只有 SNI 是 workers.dev 时握手失败**——这是 SNI 阻断，不是 IP 封锁。

### 三、沙箱代理也不放行

本机代理是 `http://127.0.0.1:9688`（由 sandbox-cli 提供，不是你的代理客户端）。逐域名实测：

| 域名 | 走代理 |
|---|---|
| `github.com` | 200 ✅ |
| `api.github.com` | 200 ✅ |
| `www.cloudflare.com` | 200 ✅ |
| `photoatelier-api.photomagic.workers.dev` | 000 ❌ |
| `example.workers.dev` | 000 ❌ |
| `photo.ronineymessjrstudio.cn` | 200 ✅ |

连 `example.workers.dev` 都不通，说明**整条 `*.workers.dev` 被排除**，与本项目无关。

### 四、你自己的代理没开

`7890 / 7897 / 7891 / 10809 / 10808 / 1080 / 2080 / 8080` **全部空闲**。
`9688` 是沙箱进程，`9160` 是 WorkBuddy 自己的服务代理。所以当前没有任何能翻出去的通道。

### 五、线上前端本来就打不开

`index.html` 三处硬编码了 `https://photoatelier-api.photomagic.workers.dev`。也就是说**线上页面在国内打开时，所有 API 调用都会挂**——这就是之前只能在本地 8125 跑的根本原因，跟你的操作无关。

## 修法：让浏览器不直连 workers.dev

Cloudflare 内部网络不受影响，所以让**边缘节点替浏览器去取**：

```
浏览器 → /api/*（同域，photo.ronineymessjrstudio.cn）
        → Pages Function（跑在 Cloudflare 边缘）
        → fetch 到 photoatelier-api.photomagic.workers.dev（CF 内网，秒通）
        → 原样返回
```

好处：

- 不用绑新域名、不用买代理；
- 前端调同域，**顺带把跨域问题也解决**；
- 本地开发依然走本地 API（`location.origin` 在 8125 上就是本地地址），一套配置两处通用。

## 已改的文件

| 文件 | 改动 |
|---|---|
| `functions/api/[[path]].js`（新） | Pages Functions 代理：转发路径/查询/POST body，剥掉 hop-by-hop 头与 `content-encoding`，上游不可达返回 **502 + `API_PROXY_UNREACHABLE`** |
| `index.html`（3 处） | API base 从硬编码 workers.dev 改为 `location.origin`，保留 `localStorage.pa_api_base` 手动覆盖 |
| `assets/plan-print-export.js`（1 处） | 同上 |
| `tests/pages-api-proxy.test.mjs`（新） | 5 项：路径透传、host 改写、POST body、状态码不吞、502 兜底 |

本地验证：8125 主页 200，同域 `/api/ai/providers` 200，说明改同域后本地照常工作。

## 还差一步（需要你的 Cloudflare 账号）

Functions 要生效必须**重新部署 Pages**：

```bash
npx wrangler pages deploy . --project-name=<你的 Pages 项目名>
```

或走 Git 集成：把这次改动推到 Pages 监听的分支即可。

部署后自检一条命令：

```bash
curl -o /dev/null -w "%{http_code}\n" https://photo.ronineymessjrstudio.cn/api/ai/providers
```

返回 `200` 且是 JSON（不是 HTML）就说明代理通了。

## 备选方案（如果不想走 Functions）

给 Worker 绑自定义域名（Cloudflare → Workers → 你的 Worker → Settings → Domains & Routes → Add Custom Domain，填 `api.ronineymessjrstudio.cn`），然后在页面控制台执行一次：

```js
localStorage.setItem('pa_api_base', 'https://api.ronineymessjrstudio.cn')
```

这条路不用重新部署 Pages，但要先在 Cloudflare 里加一条自定义域名（需要该域名在同一个 CF 账号下，看起来是）。
