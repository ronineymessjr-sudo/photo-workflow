# 连续组图方法论 · 落地实现

> 依据：用户提供的 7 条方法论。结论完全同意——**程序层能保证的是"每次传同一套锁定条件、漏传即失败、每张图过质检"，不能承诺纯 prompt 保证像素级同脸。**

## 一、七条方法论 → 代码位置

| # | 方法论 | 实现 | 位置 |
|---|---|---|---|
| 1 | 先锁定"拍摄圣经"，镜头不能改写 | `locked` 字段 + `lockedHash`；镜头对象**没有** location/wardrobe 键，写不进去 | `continuity/build.mjs`、`run.mjs` 的 hash 校验 |
| 2 | 参考图按角色分开 | `references[]` 三档 `identity / scene / style`，各自带 `status` 与说明；风格参考必须来自用户图库 | `build.mjs`、`providers.mjs` |
| 3 | 先生成并人工确认主参考图 | `master.confirmedBy` 必须为 `human`，否则直接退出 2 | `run.mjs` |
| 4 | 九个镜头分别调用 | `shots[]` 逐条请求，每条带同组 locked、只变 `variant` 白名单字段 | `run.mjs` 的 `requests` |
| 5 | 图像服务必须支持参考图 | `assertCanGenerate()` 缺角色/未确认/服务不支持 → `ProviderCapabilityError`，**失败关闭** | `providers.mjs` |
| 6 | 视觉质检门，不由规划模型自判 | 7 项检查，`judge()` 输出 pass / retry-single-shot / needs-human | `qc.mjs` |
| 7 | 完整可复现记录 | 每镜追加 manifest：shotId、lockedHash、refs、promptHash、provider、seed、结果、qc | `run.mjs` → `continuity/manifest.jsonl` |

## 二、DeepSeek 的定位

按方法论核对过：DeepSeek 官方接口是**图片输入理解**，没有图像生成输出接口。所以：

- `deepseek-vision` 在 `providers.mjs` 里被登记为 `supportsReferences: false`、`canGenerate: false`、`canPlan/canReview: true`；
- 用它规划或做视觉初筛没问题；
- 一旦让它"出图"，`assertCanGenerate()` 直接抛 `当前模型不支持参考图一致性`；
- 测试 `tests/continuity-contract.test.mjs` 里锁死了这条：**文本服务不得用于生成，但可用于规划与审查**。

## 四、跑法

```bash
# 1. 生成/更新契约
node continuity/build.mjs --dir prompt-packs/2026-10-27-deepseek/series \
     --briefs briefs-format-2026-10-27.json --out continuity/groups

# 2. 干跑：检查每镜的 seed/参考角色/提示词长度，不调用服务
node continuity/run.mjs --group continuity/groups/S01-style-hanfu-court.json \
     --provider gpt-image-2 --dry-run

# 3. 现状：会直接失败关闭，因为三张参考图还是 pending
#    → 把三张参考图落盘，改 status 为 confirmed，master.confirmedBy 设为 human
```

当前实测到的两种退出：

| 情况 | 结果 |
|---|---|
| 参考图未确认 | 退出 2：`当前模型不支持参考图一致性：gpt-image-2（参考图未确认：…-identity、…-scene、…-style）` |
| 主参考图未人工确认 | 退出 2：`主参考图未经人工确认（master.confirmedBy != human）` |
| 锁定字段被改 | 退出 2：`锁定字段被改写：当前 … ≠ 契约 …` |
| 用 DeepSeek 出图 | 退出 2：`当前模型不支持参考图一致性：deepseek-vision` |
| 没有图像适配器 | 退出 3，manifest 写 `not-attempted`，**不伪造成功** |

## 五、诚实边界

- **能保证**：每次请求携带同一套 locked 与同一组参考；漏传参考就失败；每张图必须过质检；每个产物可追溯到 lockedHash 与 promptHash。
- **不能保证**：仅靠文字 prompt 得到像素级同一张脸。要接近"同一模特连续拍摄"，必须用支持人物参考的图像服务（GPT Image 编辑模式 / Flux Kontext / IP-Adapter FaceID），并以实际九宫格测试验证。
- 本仓库目前**没有**图像服务凭据，所以 `run.mjs` 走到真实调用时会显式失败并记录，不会假装出图成功。

## 六、下一步最值得改的三处（按方法论）

3. 把 `qc.mjs` 的 7 项接成出图后的必过流程，未过只重做该镜并保留失败原因。
