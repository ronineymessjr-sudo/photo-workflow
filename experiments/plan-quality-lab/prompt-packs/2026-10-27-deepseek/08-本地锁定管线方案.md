# 本地锁定管线方案（锁脸 / 锁场景 / 锁姿势）

## 一、为什么必须走本地

你的判断是对的。**纯文生图锁不住人**，原因是机制层面的：

- 文生图每次调用都从随机噪声重新"采样"一个人脸，提示词只能描述"一类人"，不能指向"同一个人"；
- 换景别、换机位后，模型对同一段文字的理解会变，脸就更漂；
- 云端接口（GPT Image / 各类 API）不给种子、不给 face embedding、不给 ControlNet，你没有任何抓手；
- 上一批 3 张汉服拼贴换了 3 张脸，就是这个机制的必然结果，不是提示词写得不好。

**能真正锁住的只有四种东西**：人脸 embedding、参考图条件、结构控制图、固定种子。这四样只有本地管线能给。

## 二、你本机现状（已实测）

| 项目 | 状态 |
|---|---|
| 显卡 | RTX 4060 Laptop，**8GB 显存**，驱动 566.24 |
| ComfyUI | 装了两份便携版（`ComfyUI_windows_portable`、`..._cu126`），**checkpoints 与 custom_nodes 都是空的** |
| 模型 | 无 checkpoint、无 IP-Adapter、无 ControlNet、无 insightface |

所以现在的瓶颈不是方案，是**本地还缺组件**。

## 三、锁定分工表

| 要锁的东西 | 用什么 | 权重建议 | 说明 |
|---|---|---|---|
| **同一张脸** | IP-Adapter FaceID（PlusV2） | 0.8–0.9 | 由 insightface buffalo_l 提 embedding，这是刚需 |
| 同一张脸（更强） | PuLID 或 InstantID | 0.7–0.9 | 更像本人，但吃显存，8GB 要 768×1152 以下 |
| **同一处场地** | ControlNet depth（真实场地照片） | 0.5–0.6 | 墙、窗、楼梯结构被钉住，比文字描述可靠得多 |
| 同一套陈设/色调 | IP-Adapter 参考图（场地照） | 0.3–0.4 | 与 depth 叠加，别超过 0.5，否则人物也变 |
| 同一姿势骨架 | ControlNet openpose | 0.5–0.7 | 想复刻参考帧的站姿/走位时用 |
| 可复现 | 固定种子 | — | 本管线：`base + 系列号×100 + 帧号` |
| 同一套服装 | 提示词 + 参考图 | — | 服装最可靠的还是 img2img 从 REF 出发 |

## 四、装什么（8GB 显存可行路线）

**路线 A（推荐，稳）**：SDXL 写实底模 + IP-Adapter FaceID
- 底模：`realvisxlV50_v50Bakedvae.safetensors`（约 6.5GB）
- 节点：`ComfyUI_IPAdapter_plus`（cubiq）
- 依赖：`insightface` + `onnxruntime`，模型 `buffalo_l`（约 280MB）
- 输出 832×1216，30 步，CFG 5.5，dpmpp_2m/karras

**路线 B（更快更省）**：SD1.5 写实底模 + FaceID，512×768 出图再放大
- 8GB 完全无压力，但细节与真实感弱一档

**路线 C（最像真人，最吃显存）**：Flux dev fp8 + PuLID-Flux，需 1024 以下并开 lowvram，8GB 会很慢

下载清单（放到 ComfyUI 对应目录）：

| 文件 | 目录 | 大小 |
|---|---|---|
| realvisxlV50_v50Bakedvae.safetensors | `models/checkpoints/` | ~6.5GB |
| ip-adapter-plus-face_sdxl_vit-h.safetensors | `models/ipadapter/` | ~850MB |
| CLIP-ViT-H-14-laion2B-s32B-b79K（IPAdapter 用） | `models/clip_vision/` | ~2.5GB |

## 五、怎么跑

已写好的三个件（都在 `experiments/plan-quality-lab/comfy/`）：

| 文件 | 作用 |
|---|---|
| `series.config.json` | **唯一配置源**：底模、FaceID 预设与权重、采样参数、场景/姿势锁、种子规则、输出尺寸与目录 |
| `preflight.mjs` | 预检：ComfyUI 是否在线、节点是否齐全、模型是否在盘、insightface 是否就位，并直接告诉你缺什么、怎么装 |
| `run-series.mjs` | 按系列逐帧排队生成：读系列包里的锁与提示词 → 注入参考图 → 固定种子 → 按 `{用例ID}__{镜号}.png` 存回 `returned/local-comfy/` |

命令：

```bash
# 1. 启动 ComfyUI（另开窗口）
ComfyUI_windows_portable\ComfyUI_windows_portable\run_nvidia_gpu.bat

# 2. 预检
node comfy/preflight.mjs --config comfy/series.config.json

# 3. 干跑（不发请求，只看每帧的种子/尺寸/节点数）
node comfy/run-series.mjs --series S01 --config comfy/series.config.json --dry-run

# 4. 正式跑（先把定妆帧存成 style-hanfu-court__REF-A.png）
node comfy/run-series.mjs --series S01 --ref "D:/shots/ref-a.png"

# 5. 想同时锁场地与姿势
node comfy/run-series.mjs --series S01 --ref ref-a.png --venue garden.jpg --pose ref-a.png
```

## 六、Config UI 怎么对应

你说的"本地 config UI"其实就是 ComfyUI 自己那套面板，对我们来说只有三处需要动：

1. **IPAdapterUnifiedLoader 的 preset** 选 `PLUS FACEID`（不是 `PLUS`，后者只锁风格不锁脸）；
2. **IPAdapter 的 weight** 0.85 起，人脸还不像就往 0.9 加；超过 0.95 会出现"贴脸"的塑料感；
3. **ControlNet depth 的 strength** 0.5–0.6，太高会把人物也按在场地照片的轮廓里。

`series.config.json` 与这三个值是同一份参数的镜像——改配置文件和改 UI 效果一样，配置文件的好处是可批量、可版本化、可被脚本复现。

若要把这套接进 PhotoAtelier 的网页设置页，只需要一个"本地管线"面板读这份 JSON（底模 / FaceID 权重 / 场景锁开关 / 种子基数），后端把 `run-series.mjs` 的逻辑包成一个接口即可。

## 七、8GB 显存注意事项

- 启动加 `--lowvram`（或 `--normalvram` 试），batch 固定 1；
- 分辨率别超 832×1216，超了会 OOM 或脸部崩坏；
- PuLID/InstantID 与 FaceID 不要同时开，二选一；
- 出图后建议做 **img2img 低重绘 0.15–0.25**（提示词只写 `35mm film scan, natural grain, unretouched skin`）+ 5–8% 颗粒，这一步对去 AI 味比调提示词更有效。

## 八、验证是否真锁住了

用 InsightFace 比对每帧与 REF 的人脸余弦相似度：

| 相似度 | 判定 |
|---|---|
| ≥ 0.55 | 同一人（可用） |
| 0.40–0.55 | 疑似换脸（优先重出，或只留侧脸帧） |
| < 0.40 | 换人了（废片） |

场景锁定看结构：把每帧与场地参考照做 depth 边缘重合度目测，墙体、门窗、台阶的位置不应偏移。
